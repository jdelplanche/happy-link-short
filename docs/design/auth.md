# Auth

> **⚠️ Three rules that are shipped code, not suggestions:**
>
> - **SSO buttons:** render `<SocialAuthButtons>` from
>   `@/components/base/social-auth-buttons` on the auth surface (`/auth`). Never
>   hand-roll a "Continue with Google" button and never restyle it with the theme
>   colour. OAuth goes through the Lovable managed broker inside that component.
> - **Redirect:** always `${window.location.origin}/auth/callback` — never a bare
>   origin, which strands the user on the marketing landing.
> - **Providers:** this project has **Google only**. Pass `providers={["google"]}`.
>   A button for a provider the project has not configured can only ever error.

Auth is real Supabase auth — Google SSO and email/password. It is not simulated,
not deferred, not a SPEC-GAP.

## OAuth

Never call `supabase.auth.signInWithOAuth` directly — Google is a secretless
managed provider here, so a direct GoTrue call fails with `missing OAuth secret`.
`SocialAuthButtons` calls the broker for you and always sends the user to
`${window.location.origin}/auth/callback`.

## Why `/auth/callback` has to exist

`SocialAuthButtons` hardcodes that path. Without the route, SSO dead-ends on a
404. The page handles **both** ways the broker can return a session — fragment
tokens (`#access_token=…`) and a PKCE `code` (`?code=…`) — then lands the user on
`DEFAULT_AUTHED_ROUTE` (`/links`), never `/`. It also redeems a pending anonymous
link claim, so a visitor who shortened a link on the landing page and then signed
in with Google keeps that link.

The route is a literal two-segment path, so React Router's ranking keeps it clear
of the `/s/:slug` short-link resolver. Neither can shadow the other.

## Every redirect in this app

| Flow | Redirect | Why |
|---|---|---|
| Google OAuth | `${origin}/auth/callback` | Only page that can turn the broker's return into a session |
| Sign-up confirmation (`emailRedirectTo`) | `${origin}/auth/callback` | A bare origin cannot exchange the confirmation code, so the user lands signed OUT |
| Password reset (`redirectTo`) | `${origin}/auth` | **Deliberately not** `/auth/callback` — that would sign the user straight in with no chance to set a new password |

## The leave affordance — log out / exit demo

The app ships two route trees over the same components: `/*` (Supabase-backed,
authenticated) and `/demo/*` (seed data, no auth). Because they share components,
the leave affordance must differ, and `useIsDemo()` (`src/lib/demo.ts`) is the ONE
thing that decides it. Never re-derive demo-ness from the pathname in a component.

- **Authenticated `/*`** → "Log out", calls `signOut()` from the AuthProvider.
- **Public `/demo/*`** → "Exit demo" with a close icon, a plain navigation to
  `EXIT_DEMO_ROUTE` (`/`). The demo has no session, so signing out is meaningless.

It appears in two places, and both are already wired:

- the avatar dropdown in each top bar (`links`, `links-detail`, `settings`);
- the Account section of Settings → General (`general-tab.tsx`).

Layout rule: the leave affordance sits ABOVE settings and the account row, and the
account row is always last.

```tsx
const isDemo = useIsDemo();
...
{isDemo ? (
  <Link to={EXIT_DEMO_ROUTE}>
    <IconX className="size-4" />
    Exit demo
  </Link>
) : (
  <button onClick={handleLogout}>Log out</button>
)}
```

This app uses a top-bar layout, not a shadcn `Sidebar`, so it wires these
primitives directly rather than mounting a shared sidebar footer component (that
would need `SidebarProvider`). Keep it that way.
